# סיכום ניהולי ואנליטיקה — UI-4

## היקף

שני מודולי מסך בשלוש כתובות קיימות: `/admin`, `/admin/dashboard`, `/admin/analytics`. מימוש וחוזי API בחבילה נפרדת בתוך UI-4, לא שלב כללי חדש. הקבלה מתועדת בדוח המסירה לפי SHA ו־CI; אין להסתמך על מסמך זה כראיה להפעלה בייצור. אין מיגרציה, חיבור ספק, merge או deploy.

## מקור ומשמעות

`GET /admin/dashboard/stats` ו־`GET /analytics/comprehensive?days=...` משתמשים בחוזה סיכום רשומות ישיר: owner_context, as_of, filters, counts, distributions, recent_users, recent_payments, daily_activity. ספירות המשתמשים, האתגרים והתשלומים מתייחסות רק לרשומות בתחום המנהל. root מפורש יכול לקבל תחום פלטפורמה; כל מנהל אחר רק tenant והיררכיה מאומתים. האתגר חייב להתאים למותג של בעליו ולתוכנית באותו מותג. שדה מצב KYC/אתגר/תשלום אינו סמכות זהות, מימון או סליקה.

דשבורד מציג עד חמישה משתמשים ועד חמישה תשלומים אחרונים. משתמשים מוצגים באמצעות מזהה וקודים רשומים ללא שם, אימייל או פרטי קשר בתגובת API. סכום תשלום הוא Decimal string/null ומטבע רשום בלבד, בלי הנחת USD/USDT, סיכום מטבעות שונים או כותרת הכנסות. `record_verification=unverified_legacy`, `settlement_enabled=false`. מדדי צמיחה קשיחים, דירוג אפיליאטים, conversion ו־revenue אינם חלק מחוזה המסכים החדש.

אנליטיקה תומכת ב־7/30/90/180/365 ימים קלנדריים של UTC, כולל היום ועד as_of. סיכום יומי מתייחס ליצירת רשומות בלבד; החלון אינו זמן של מעבר funded/completed ואינו מדידת מסחר. סטטוסים הם המצב הרשום כעת של רשומות שנוצרו בחלון. רשומה עם created_at חסר אינה נספרת בחלון; null אינו מתוקן לתאריך מומצא. רשומות עתידיות אינן נכללות. אפס בספירה הוא COUNT אמיתי, לא תחליף לכשל SQL. תאריכי UTC נאיביים היסטוריים מסוריאלים עם Z מפורש; המיון משווה זמן אמיתי ו־ID ולא טקסט ISO משתנה, והלקוח שומר מיקרו־שניות להשוואת סדר ו־as_of.

## גבולות קריאה ותצוגה

תחימת JWT/admin/tenant/hierarchy לפני SQL משאב, אימות פרמטרי query קנוניים, no-autoflush ו־statement timeout. count/distributions/recent/daily מאותו SQL statement snapshot; אין ORM serialization, לולאת שאילתות לפי משתמש או all של נתוני מסחר. שני handlers אלה אינם משתמשים במטמון משותף; רענון מפורש מאפשר לקבל תחימה חדשה ולא cache של הרשאה קודמת. יתר routes היסטוריים של analytics מחוץ לחבילה ואינם מקור נתוני המסכים החדשים.

חוזה לקוח מאמת בעלות מול auth עצמאי, סכומים/תאריכים/filters/cardinality/sums וקודים. רכיב מבודד לפי auth/id/tenant/role/days, ביטול עד Axios; תוצאה מאוחרת אינה משיבה נתוני הקשר קודם. רענון session באותו principal אינו GET חדש, אין polling/refresh אוטומטי או replay אחרי 401. טעינה, כשל וריק נפרדים עם alerts ונגישות.

## עיצוב ומעטפת

navy/slate והדגשת cyan, כרטיסי counts ומצב מקור ברור, טבלאות/ברים נגישים במקום גרפי כסף שאינם מאומתים. מעטפת אחת, טבלאות בגלילה פנימית, תאריכים וטקסט ארוך תחומים. אין צ׳אט צף מעל הנתונים. חיפוש המעטפת הישן ללא handler הוחלף ב־My support tickets; תפריט נייד בעל שם ו־aria-expanded, מצבי focus ומופעי תנועה רצופה הוסרו מהניווט. קישורי מסכי משתמשים/אתגרים/תשלומים/KYC קיימים, ואין הפניה לנתיב משתמש פרמטרי שאינו קיים.

## מה נשאר

אין השלמת UI-4 כולו: ניהול משתמשים, תוכניות, אתגרים, KYC, CRM והגדרות עדיין דורשים בדיקה ומימוש לפי המפה. UI-5/6 והחלטות עסק/נוסחים ותוכן דינמי ב־UI-3 פתוחים. חיבור ארנק ו־MT5 נשאר נפרד. פריסה תיעשה לגרסה סגורה עם גיבוי/חזרה ואישור מתאים, ולא כתוצאה מהצלחת CI בלבד.

## קבלה בחבילה

30 מקרי App סינתטיים ותשעה מקרי build/הרשאות בשלוש כתובות; parity של תגובות Flask אמיתיות מול principal ובקשה עצמאיים, בדיקות PostgreSQL זמניות ל־snapshot ודיוק חלקי שנייה, רגרסיות וביקורת סגירה לפי דוח המסירה. כל aria-labelledby באזורי recent/daily מפנה לכותרת קיימת. CI וה־SHA המדויק נרשמים בדוח, ואינם פריסה או אישור ספק.
