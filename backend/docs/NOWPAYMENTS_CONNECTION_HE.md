# חיבור NOWPayments — שמירת סודות והכנת קוד השרת

תאריך: 2026-10-12. העבודה בענף `fix/security-foundation-20261011` וב־PR טיוטה בלבד.

## מה הושלם בחשבון וב־Manus

בחשבון NOWPayments קיים מפתח API ייעודי עם התווית `MarketEdgePros — dedicated backend integration — 2026-10-12`. מפתח הפרויקט האחר נשאר ללא שינוי. לא שונו כתובות ארנק, הגדרות העברה או כתובת webhook.

מפתח ה־API הייעודי וסוד ה־IPN החדש הועתקו דרך לוח ההעתקה ישירות לשדות הסודות של חיבור Manus הקיים. השמירה אושרה בממשק ושני המשתנים זמינים במשימה. סוד ה־IPN שנשלח בצ׳אט בוטל באמצעות regeneration; החדש לא נשלח כהודעת צ׳אט. אין לכלול סודות בדוחות, commits, artifacts או frontend. כלי אוטומציה עשויים לכלול ערכים בחילוץ מסך של טופס בעת ההדבקה: אין לטעון שהערכים מעולם לא הופיעו בפלט כלי.

ה־IPN הוא סוד חתימת HMAC-SHA-512 של callbacks, לא מפתח API ולא קוד PIN. הוא מוגדר ברמת חשבון הספק, לא כהוכחה לבידוד לפי API key. כל מערכת אחרת המשתמשת ב־IPN באותו חשבון חייבת להתאים לסוד החדש. מפתחות ה־API עצמם לא שונו במהלך ההחלפה.

קריאת אימות `GET /v1/estimate?amount=1&currency_from=usd&currency_to=btc` חזרה HTTP 200 עם שדות estimate תקינים כשהשתמשה במפתח השמור, ו־HTTP 403 ללא מפתח. זאת קריאת שער בלבד: לא נוצר תשלום, לא נשלחו כספים, לא נבחרה רשת USDT ואין קביעה ששער זה הוא מחיר להזמנה. `/status` לבדו אינו מוכיח אימות.

## חיבור טיוטת האתר

`backend/src/config.py` טוען בצד השרת בלבד את `NOWPAYMENTS_API_KEY` ו־`NOWPAYMENTS_IPN_SECRET` מסביבת התהליך. ערך חסר או ריק נשאר `None`. `TestingConfig` מאפס את שניהם; בדיקות משתמשות רק בסודות סינתטיים שמוגדרים במפורש.

הקוד אינו מעתיק סוד מ־Manus לשרת אוטומטית. בשרת נדרש מקור סוד נפרד ומוגן. אין prefix של `VITE_`, אין ערך סוד בדוגמת הסביבה ואין חשיפת הסוד ללקוח. `backend/.env.example` מתעד שמות בלבד.

### גבול אימות האישורים

`NOWPAYMENTS_API_KEY` הוא אישור גישה שמונפק על ידי הספק, ואינו סוד חתימה שנוצר מקומית. לכן `is_valid_nowpayments_api_key` מבצע בדיקת צורה מקומית ומוגבלת בלבד: ASCII מודפס באורך 16–512, ללא רווחים או תווי בקרה, ללא ערכי placeholder/weak, ולפחות שמונה תווים מובחנים. הבדיקה אינה טענת אימות מול הספק; רק בקשת ספק מורשית יכולה לאמת את האישור.

לעומתו, `NOWPAYMENTS_IPN_SECRET` הוא סוד HMAC-SHA-512 שנוצר לחתימת callbacks, ולכן נשאר תחת דרישת המינימום של 32 תווים, כפי שנשארות דרישות סודות ה־JWT וה־runtime. אין להחליף בין שני סוגי האישורים או להסיק מאורך מפתח API דרישת אורך לסוד חתימה.

נוכחות המפתחות **אינה מפעילה גבייה או settlement**. יצירת תשלום, סטטוס ספק בלתי משויך וה־checkout הישנים נשארים fail-closed. חתימת IPN תקינה עדיין מובילה ל־503 `ORDER_SETTLEMENT_NOT_CONFIGURED`: אין להגדיר את הנתיב כ־callback חי לפני השלמת מנגנון settlement, אחרת הספק עשוי לנסות לשלוח שוב. לא השתנה חוזה החתימות המוגבל של ה־legacy, ובפרט עדיין אין תאימות מלאה לערכי JSON עשרוניים.

## מה עדיין נדרש באתר

לפני שמירה בשרת DigitalOcean יש לאמת את השירות ואת יעד הסודות, להציג את השינוי המדויק ולקבל אישור נפרד. לא בוצעו SSH, שינוי בייצור, restart, deploy או migration במסגרת החבילה הזאת.

לגבייה ממשית נדרשים adapter ספק מול הזמנה קנונית ומחיר שרת קפוא, שיוך payment ID להזמנה ולבעלים, אימות callbacks תואם־ספק, inbox עמיד ומניעת כפילויות, settlement אטומי והענקת זכאות פעם אחת. נדרשות גם בחירה מפורשת של מטבע/רשת ומדיניות עמלות, חוסר/עודף תשלום ו־expiry. אין להמציא בחירות אלה ואין להפעיל MT5, משיכות או affiliate payout באמצעות שמירת המפתחות.
